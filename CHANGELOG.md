# Changelog

All notable changes to **KC DevKit** will be documented in this file.

## [1.4.0] — 2026-09-07

### Added

- **Excel / CSV preview** — custom readonly editor (`kcDevKit.excelPreview`) for `.xlsx` / `.xlsm` / `.xls` / `.csv`. Opens in Cursor/VS Code instead of a binary dump.
- xlsx/xlsm parsed with **ExcelJS** (MIT): sheet tabs, freeze panes, column widths, wrap text, fills/fonts, cached formula results (tooltip shows the formula).
- .xls parsed with **SheetJS Community 0.18.5** (Apache-2.0); CSV parsed as UTF-8 / UTF-16LE.
- Command `KC DevKit: Open Excel Preview` (`kcDevKit.openExcelPreview`) plus editor title button on spreadsheet files.
- Setting `kcDevKit.excel.enabled` (default true) and `workbench.editorAssociations` for `*.xlsx` / `*.xlsm` / `*.xls` / `*.csv`.
- `scripts/smoke-excel.mjs` (`npm run smoke:excel`) — sheet-name / CJK / formula / wrap assertions plus HTML evidence.
- `deploy.ps1 -Publish` also publishes to **Open VSX** (Cursor public marketplace) when `OPENVSX_TOKEN` or `OVSX_PAT` is set.

### Changed

- Preview is **read-only** so saving cannot strip COUNTIF/SUM, yellow input fills, or data validation.

## [1.3.0] — 2026-08-21

### Added

- **PDF preview** — custom editor (`kcDevKit.pdfPreview`) using pdf.js canvas glyph rendering, CJK `cmaps`, and `standard_fonts` (math/Type1). Virtualized nearby-page render, file-watch reload, and error UI for missing / encrypted / invalid PDFs.
- Command `KC DevKit: Open PDF Preview` (`kcDevKit.openPdfPreview`) plus editor title button on `*.pdf`.
- Settings `kcDevKit.pdf.enabled` (default true) and `kcDevKit.pdf.defaultScale` (default `page-width`).
- `workbench.editorAssociations` default so Cursor/VS Code open `*.pdf` with this preview.
- `scripts/smoke-pdf.mjs` (`npm run smoke:pdf`) — CJK text assertion + page-1 PNG evidence.
- Cursor-aware `scripts/deploy.ps1`: prefer `cursor.cmd` / `Cursor.exe --install-extension`, keep `code`, fallback unzip into `%USERPROFILE%\.cursor\extensions\kn1ghtc.kc-devkit-1.3.0`.

### Changed

- VSIX size target raised: pdf.js + cmaps + standard_fonts are vendored under `vendor/pdfjs/` (generated by `build.ps1`; not `node_modules` at runtime). Design NFR-2 is now **&lt; 20 MB**.
- `build.ps1` copies `katex.min.css` and KaTeX `woff2` fonts from `node_modules`, copies pdf.js legacy assets, and bundles `src/pdf/webview/viewer.ts` → `preview-scripts/pdf-viewer.js`.

### Fixed

- CHANGELOG 1.2.0 listed `markdownPreview.ts`; the Mermaid plugin file is `src/markdown/markdown-it-mermaid.ts` (history below left unchanged).
- Duplicate "Step 5" comments in `build.ps1`.

## [1.2.0] — 2026-03-20

### Fixed (Critical)

- **Mermaid CSS class conflict with VS Code built-in preview** — VS Code's native Markdown preview also uses `.mermaid` class, causing style collisions and rendering failures when both are active. Changed all Mermaid-related CSS selectors and JS class references from `.mermaid` to `.kc-mermaid` to avoid namespace conflicts.

### Changed

- `mermaid-init-src.js`: observer and renderer now target `.kc-mermaid` class
- `mermaid.css`: all selectors updated to `.kc-mermaid` namespace
- `markdownPreview.ts`: Mermaid code blocks emit `<div class="kc-mermaid">` instead of `<div class="mermaid">`

## [1.1.0] — 2026-03-19

### Fixed (Critical)

- **Mermaid preview crash on large documents** — Opening a 65 KB document with 20+ mermaid diagrams caused black screen and VS Code process crash. Root cause: all diagrams rendered synchronously in a tight loop with no throttling or viewport culling.

### Changed

- **Mermaid rendering rewritten**: IntersectionObserver-based lazy rendering — diagrams only render when scrolled into viewport (200 px pre-fetch margin)
- **MutationObserver debounced** (300 ms) — prevents render storms during preview content updates
- **Serial render queue** — one `mermaid.render()` call at a time to cap webview memory usage
- Mermaid CSS: added visual loading placeholder ("⏳ Rendering diagram…") for unprocessed diagrams

### Improved

- **Unified version management** — `package.json` is the single source of truth; `build.ps1` and `deploy.ps1` now read and display the version automatically
- README: Install instructions updated to reference Marketplace directly
